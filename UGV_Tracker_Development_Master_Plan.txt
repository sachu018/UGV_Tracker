UGV Tracker Development Master Plan

Vision

Build a professional ESP32 + Quectel EC200U-CN based standalone UGV
tracker with a custom FastAPI backend, SQLite persistent database,
and a dark glassmorphic Leaflet live map web dashboard.

Project Structure

    UGV_Tracker/
    ├── backend/           # Python FastAPI Server & Dashboard App
    │   ├── main.py        # FastAPI API application & routes
    │   ├── database.py    # SQLite database storage & queries
    │   ├── ugv_tracker.db # Persistent SQLite database
    │   └── static/
    │       ├── index.html # Dark Mode Command Center UI
    │       ├── style.css  # Glassmorphic CSS Design System
    │       └── app.js     # Leaflet Map & Telemetry Poller
    ├── include/
    │   ├── Config.h       # Pin definitions, APN, Server URLs, timing constants
    │   ├── EC200U.h       # Low-level EC200U driver interface & AT commands
    │   ├── GPS.h          # High-level GPS module interface
    │   ├── HTTPClient.h   # Telemetry JSON formatting & HTTP client
    │   ├── Network.h      # Cellular registration & signal monitoring
    │   ├── Types.h        # GPSData, TelemetryData, TrackerState data types
    │   └── Tracker.h      # Master Application State Machine
    ├── src/
    │   ├── main.cpp       # Minimal entry point (setup & loop)
    │   ├── EC200U.cpp     # EC200U modem driver implementation
    │   ├── GPS.cpp        # GPS high-level wrapper implementation
    │   ├── HTTPClient.cpp # HTTP serializer implementation
    │   ├── Network.cpp    # Cellular network helper implementation
    │   └── Tracker.cpp    # Tracker state machine implementation
    ├── lib/
    └── platformio.ini     # ESP32 environment configuration & dependencies

Development Roadmap & Progress

Phase 1 (Completed)
- UART communication setup
- SIM detection verified
- LTE registration verified
- Internet connectivity verified
- NTP sync verified
- GPS Fix verified (14-16 Satellites locked at 10.8086°N, 76.7403°E)

Phase 2 (Completed)
- Modular C++ architecture (.h / .cpp separation)
- EC200U driver implementation
- GPS coordinate & NMEA parsing
- State Machine (BOOT -> CHECK_SIM -> WAIT_NETWORK -> ENABLE_GPS -> WAIT_GPS_FIX -> TRACK -> UPLOAD)

Phase 3 (Completed)
- Cloud telemetry upload verified (HTTP 200 OK responses over LTE)
- Google DNS (8.8.8.8) configuration added

Phase 4 (Completed)
- Built Python FastAPI REST server (`backend/main.py`).
- SQLite persistent storage (`backend/database.py`).
- API endpoints: `/api/v1/telemetry`, `/api/v1/telemetry/latest`, `/api/v1/telemetry/history`.

Phase 5 (Completed)
- Custom Dark Mode Command Center Web Dashboard (`backend/static/`).
- Interactive Leaflet.js Vector Map with CartoDB Dark tiles.
- Real-time animated UGV vehicle marker & glowing path trail.
- Digital Speedometer (km/h), Satellite counter, LTE Signal meter, Battery level & Haversine distance calculator.

Phase 6 (Next: Advanced Features)
- Geofencing boundaries & alerts
- Anti-theft motion detection
- Offline SD/Flash buffering when out of cellular coverage
- Fleet management support

Coding Rules

1. main.cpp should only initialize and call update().
2. Never place raw AT commands outside EC200U.cpp.
3. Separate hardware, networking, and application logic.
4. Test each module independently before moving to next phase.
5. Commit to Git after each completed milestone.
